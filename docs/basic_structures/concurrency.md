# Работа с горутинами и каналами

```
    // Горутины
    go func() {
        // параллельное выполнение
    }()
    
    // Каналы
    ch := make(chan int)
    go func() { ch <- 42 }()
    value := <-ch
    
    // Select для работы с несколькими каналами
    select {
    case msg := <-ch1:
        // ...
    case msg := <-ch2:
        // ...
    case <-time.After(time.Second):
        // таймаут
    }
```

## Как это работает?

### Горутины

Горутины это функции, который выполняются параллельно работе основной функции (main). Для объявления горутины используется
используется ключевое слово go. 

```
package main
import "fmt"
  
func main() {
      
    for i := 1; i < 7; i++{
        go sum(i)
    }
    fmt.Println("The End")
}
  
func sum(n int){
    result := 0
    for i := 1; i <= n; i++{
        result += i
    }
    fmt.Println(n, "-", result)
}
```

В примере выше функция sum запускается в отдельной горутине для каждого значения, это значит что вычисления будут
выполняться параллельно. То есть при каждой итерации цикла фор запускается функция sum для нового значения, но но мы не ожидаем
ее завершения, а просто запускаем функцию с уже новым значением.

В данном примере ответ может быть разным при каждом запуске, и может быть просто "The End". Дело в том что основная горутина
main не ждет завершения всех горутин, и если она завершится быстрее мы не увидим результата работы остальных горутин.

Для того чтобы дождаться выполнения горутин в данном случае можно использовать встроенный пакет time, а именно его функцию
Sleep

```
func main() {
      
    for i := 1; i < 7; i++{
        go sum(i)
    }
    time.Sleep(200 * time.Millisecond)
    fmt.Println("The End")
}
  
func sum(n int){
    result := 0
    for i := 1; i <= n; i++{
        result += i
    }
    fmt.Println(n, "-", result)
}
```

Тут 200 миллисекунд должно хватить на завершение всех горутин. Вывод будет примерно таким:

```
3 - 6
4 - 10
1 - 1
2 - 3
5 - 15
6 - 21

The End
```

Примерно - из-за того что нет четких гарантий того что горутина запущенная первой - первой завершится.

   WaitGroup
   
Пакет sync дает нам иструмент для работы с горутинами. 

В примере буду использовать методы:
 - wg.Add - добавляем счетчик горутин (указываем сколько всего горутин будет в группе)
 - wg.Done - ставим в конце горутины, чтобы обозначить что ее выполнение оконченно
 - wg.Wait - чтобы дождаться выполнения всех горутин, указанных в счетчике

```
func main() {
	var wg sync.WaitGroup
	for i := 1; i < 7; i++ {
		wg.Add(1)
		go func(n int) {
			defer wg.Done()
			sum(n)
		}(i)
	}
	wg.Wait()
	fmt.Println("The End")
}

func sum(n int) {
	result := 0
	for i := 1; i <= n; i++ {
		result += i
	}
	fmt.Println(n, "-", result)

}
```

### Каналы (channels)
Каналы используются для передачи данных между горутинами.
Если рассматривать на примере выше, то каналы можно использовать так:
```
func main() {
    results := make(chan int)

    for i := 1; i < 7; i++ {
        go sum(i, results)
    }

    for i := 1; i < 7; i++ {
        fmt.Println(<-results)
    }

    fmt.Println("The End")
}

func sum(n int, ch chan int) {
    result := 0
    for i := 1; i <= n; i++ {
        result += i
    }
    ch <- result
}
```

В данном случае мы создали небуферизированный канал. Это означает, что операции записи и чтения — блокирующие.
Чтобы отправить данные в канал, должен быть тот, кто будет из него читать, и наоборот. В противном случае получим ошибку:

 - "fatal error: all goroutines are asleep - deadlock!"

Важно: для небуферизированных каналов отправка и получение должны происходить в разных горутинах (иначе будет вечная блокировка).


Буферизированный канал

Чтобы создать буферизированный канал, используется запись:

```
ch := make(chan int, 3)
```

В таком канале могут временно храниться значения.
Мы можем использовать его в примере выше — программа будет работать так же, но разница станет заметна, если замедлить main:

```

func main() {
	results := make(chan int, 3)

	for i := 1; i < 7; i++ {
		go sum(i, results)
	}

	time.Sleep(2 * time.Second) // имитируем тормозящий consumer

	for i := 1; i < 7; i++ {
		fmt.Println(<-results)
	}
}
```

В этом случае буферизированный канал работает быстрее, потому что:
отправитель может записать несколько значений без ожидания читателя
блокировка произойдёт только тогда, когда буфер заполнится
Например, при размере буфера 3 горутина-отправитель заблокируется 
только после записи трёх значений, а небуферизированный канал блокируется 
при каждой операции отправки, пока значение не будет прочитано.
